# Unified browser safety and authorization policy v1

Accepted 2026-11-08. Applies outside the model at API admission, discovery, plan validation, every step, every network connection and artifact retrieval. [ADR-009](../adr/009-authorization-policy.md).

## Authority and local operator

One configured local operator owns projects. Bootstrap an operator session from an out-of-band local secret; store only the session-token hash server-side. Use HttpOnly, SameSite=Strict session cookies, exact trusted UI Origin/Host checking and CSRF tokens on mutations; Secure cookies are required under HTTPS. Loopback HTTP is permitted only for the local demo. Never put a provider key in the browser or a session token in a URL. No wildcard CORS; missing/untrusted Origin on browser mutations is rejected. CLI access uses a separately scoped operator credential. Bind published ports to loopback; Redis, Postgres and runner ports are not host-published. This is a local operator model, not enterprise identity.

Creating a project references an existing operator-configured fixture authorization; it never creates or expands approval from arbitrary submitted URLs. Authorizations record fixture owner, permission evidence reference, exact origin, paths, allowed operations, issue/expiry/revocation time and immutable policy version. Initial validity is explicitly set, at most seven days; no perpetual default. Revocation remains mutable and is checked in addition to the immutable run snapshot. The operator can revoke immediately; changing scope creates a new version. UI approval never bypasses policy. External forms, non-fixture sites, production logins, purchases, deletion, account changes, external messages and security scans are prohibited even if clicked through an approval screen.

## URL and network rules

- A fixture deployment manifest binds one service name, resolved container address and port. The runtime installs a static per-run mapping; the runner has no general DNS access. No host network, Docker socket, host-gateway mapping or broad private-range exception.
- Target URLs use HTTP/HTTPS with exact normalized scheme, lowercase ASCII host and effective port. MVP hostnames are ASCII fixture service names from the manifest; user-supplied IP literals, Unicode/IDNA alternatives, userinfo and trailing-dot aliases are rejected. Public DNS/nonlocal support is deferred until connection-time resolution/pinning is independently implemented and tested.
- Plans contain origin-relative absolute paths only. Parse and canonicalize once in trusted code; reject scheme-relative paths, backslashes, control/NUL bytes, percent-encoded separators/dots/percent signs, dot segments and double-encoding. No string-prefix origin test. Allow exact paths, or explicitly declared segment-bounded subtree rules; reject unapproved query keys/values. Fragments are disallowed in v1.
- Check redirects before following, not only after landing. Check every resource/fetch/iframe request against origin/path/method rules. Network firewall permits only the fixture's pinned address/port, with no route to host/metadata/internal services/provider/Internet. Application routing additionally limits paths/methods within that fixture.
- Deny popups/new windows, WebSockets, service workers, downloads, file uploads, external protocols and arbitrary blob/data navigation. Abort dialogs and classify unsupported interaction as test_error. No persistent browser profiles, extension, clipboard or OS automation access. Block IPv6/alternate transports unless explicitly needed and covered by equivalent rules.
- Only named synthetic operations may use POST; no PUT/PATCH/DELETE or arbitrary API submission action. Known read-only GET/HEAD paths are allowed. Navigation to a mutating GET route is denied unless the explicit fixture operation permits it. Form targets and resulting requests must match the approved operation manifest.

Static IP/port enforcement is necessary but not sufficient for allowed same-origin requests; the runner enforces paths/actions too. Request interception alone is not the isolation boundary. Independent namespace tests must show the browser cannot reach the control channel, DB, Redis, API, provider or host. Unexpected destination, ambiguous authorization or expired capability stops execution; record `policy_blocked` as an error category, never a product defect.

## Actions and synthetic mutations

The only actions are navigate, click, fill, assert_visible and assert_url as specified in the [plan contract](../contracts/test-plan-v1.md). Locators use exact role/name or exact visible text; exactly one element must match. Fill targets must be approved fixture fields and values must match finite synthetic values or bounded fixture-provided generators selected by trusted code. Block password/secret fields except a separately declared synthetic login-rejection field with fake values and no persistence. A fixture never sets cookies or sends authentication headers; detecting either stops capture/execution and quarantines temporary evidence.

All clicks, fills and navigation routes are checked against the fixture operation manifest, including controls that can mutate without a form. Before starting a run the operator approves this versioned manifest of safe operations and reset procedure; compliant fixture plans can then execute without per-plan approval. Unknown control behavior fails closed. Empty fill is permitted for validation tests. Reset runs only via a fixed trusted fixture-reset protocol, not a model-selected URL/command; its endpoint is inaccessible to page scripts and resets only the leased run fixture.

## Data, evidence and budget controls

Send only bounded selected accessibility/DOM metadata and public oracle requirements to the planner. Treat objective text as subordinate user intent, never permission to override policy. Page content, URLs and model output are untrusted. Raw HTML, screenshots, traces, headers, cookies and storage state never enter model requests. No arbitrary executable code, CSS/XPath selectors, regex programs or model-defined network tools.

Capture only reviewed synthetic fixtures; traces are not assumed sanitizable. Prevent collection of real secrets by fixture design and capture configuration. On unexpected sensitive content, halt and discard/quarantine with no user download until deletion; preserve only safe incident metadata. Serve artifacts by opaque ID after operator/run ownership, expiry and integrity checks, never by submitted path. No inline HTML or active trace rendering; use safe downloads and an isolated trace viewer. Storage writes use per-run temporary space and trusted ingestion; no shared host directory in the runner.

Use the [baseline limits](baseline.md). Recheck deadlines/revocation at every step; active runner capability expires no later than lease expiry. Budget/quota exhaustion yields explicit partial/inconclusive/error results, never automatic success. CPU/RAM/time/storage caps and process cleanup are release gates. No runtime exception broadens network or action permissions.
