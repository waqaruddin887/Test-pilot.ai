# Database and evidence model v0.2

Accepted 2026-11-08. Logical migration baseline; no SQL migration/application model has been implemented. PostgreSQL is authoritative. Redis transports fixed job IDs and never determines findings or authorization. Primary entities have UUID `id`; ManifestArtifact uses the explicitly specified composite primary key. Timestamps are UTC `timestamptz`. Mutable rows have integer `version` for compare-and-swap. Fields marked nullable are the only optional relations specified below. [ADR-007](../adr/007-durable-jobs.md), [ADR-008](../adr/008-verification-review.md), [ADR-010](../adr/010-evidence-evaluation.md).

`Finding` ↔ `EvidenceManifest` and self-referencing attempts can be assembled within a transaction with deferrable FKs; insertion ordering does not justify omitting integrity. Stable public oracle refs use `requirement_key@revision`, never private defect IDs.

OracleVersion content is immutable from creation; reviewed_by/reviewed_at can be populated once as an atomic review-and-seal operation before first planner/executor use. Subsequent edits require a new revision. EvidenceManifest is assembled privately and published once; the manifest content/hash and finding binding are sealed together, with no later rebinding to a different finding.

ExecutionSlot is provisioned by migration and cannot be deleted by a worker. Claim locks the slot and job in one transaction; release requires a matching job/epoch and supervisor teardown acknowledgment. WorkerCapability is a liveness record, not authority to approve targets. JobCommand payloads/receipts contain only bounded sanitized control data; uncertain send state is not permission to retry. Provider request intent is similarly recorded in PlannerRequest before any request can leave the process.

## Integrity and indexes

Use composite unique keys/FKs (run, case, attempt, result) to prevent cross-run relations, not just independent UUID validity. Enforce the same project on Run/Authorization/rerun parent, same case on reproduction/initial links, and same run on manifest/artifact/finding links. Append-only records are not updated to rewrite historical results. Enforce allowed state transitions and accepted-review prerequisites transactionally with row/version locks; where SQL CHECK cannot reference other rows, use explicit transaction logic and integration tests, not a claim that an ordinary CHECK enforces it.

Index every referencing FK used in lookups, plus Run(project_id, accepted_at), Run(state, queue_expires_at), ExecutionJob(state, lease_expires_at), OutboxEvent(state, next_attempt_at), Artifact(capture_state, expires_at), RunEvent(run_id, sequence), Review(finding_id, sequence), usage day/operator and idempotency expiry. Unique constraints support deduplication; JSONB stores versioned plans/snapshots/observations with API and database byte ceilings, not a substitute for ownership. Parameterize SQL. API role cannot write evaluation labels; runner has no DB role.

Index JobCommand(job_id, lease_epoch, command_id) and WorkerCapability(enabled, expires_at); require JobCommand's run/attempt to belong to its job. WorkerCapability expiry is at most 15 seconds after heartbeat. Stale capability/command records are purged within the seven-day metadata window; never remove a live slot or an unacknowledged cleanup obligation to satisfy retention.

## Evidence publication and deletion

Runner writes only bounded ephemeral local files, then returns an artifact descriptor and bounded stream to trusted ingestion. Ingestion assigns storage_key, checks run/attempt lease, size, allowed MIME/type, SHA-256 and quota, writes temp→atomic rename, then marks available. Ignore submitted filenames/paths. Hash validation detects corruption, not authenticity against a privileged attacker. A trace is treated as an opaque downloadable archive, never unpacked into the web filesystem.

Byte TTL is 24 hours from capture; all run metadata, usage, logs, events and reviews expire seven days from run acceptance. Projects/authorization records persist until operator removal, but authorizations expire independently. Session TTL is eight hours; logs and sessions contain no captured content or plaintext secrets. Cleanup runs every minute; retrieval denies expired artifacts immediately even if physical deletion is delayed. Delete bytes first, mark artifact deleted, then delete expired run aggregates in dependency order with controlled cascades. Ownership/oracle/project deletion is restricted while referenced; archive projects until run retention completes. Cancel/delete run work before purging it. Failed deletion blocks new capture at quota and raises a safe local error. No automatic backups or exports in MVP; any later export must explicitly set privacy/retention handling and cannot silently extend default TTLs.

Expiration preserves historical review metadata only until the seven-day cutoff, with evidence-unavailable labels. Keep source oracle/fixture specs in Git; store runtime provenance hashes. Before migrations, make an explicitly requested, private local backup with a documented TTL, or document that the development data is disposable. Test fresh migration, constraints, retention and rollback/recovery; no backup has been created by this design pass.
